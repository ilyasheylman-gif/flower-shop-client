# Flower Shop Client — «Лепесток»

Клиентская часть курсового проекта «Цветочный магазин с конструктором букетов» (вариант 28).
SPA на **Vue 3** + **Vite**, маршрутизация **Vue Router**, состояние **Pinia**, запросы к API через `fetch`.
Работает с REST API из репозитория `flower-shop-api` (Laravel + Sanctum).

## Запуск

Требуется Node.js 20+ и запущенный API (`php artisan serve` → http://localhost:8000).

```bash
git clone <url> flower-shop-client
cd flower-shop-client
npm install
cp .env.example .env        # Windows: copy .env.example .env
npm run dev                 # http://localhost:5173
```

Адрес API задаётся одной переменной в `.env`:

```env
VITE_API_URL=http://localhost:8000/api
```

На стороне Laravel адрес клиента должен быть разрешён в CORS (`CORS_ALLOWED_ORIGINS=http://localhost:5173` в `.env` API).

Сборка для публикации: `npm run build` (результат — в `dist/`).

## Порядок полной проверки

1. API: `php artisan migrate:fresh --seed` и `php artisan serve`.
2. Клиент: `npm run dev`, открыть http://localhost:5173.
3. Войти под тестовой учётной записью (кнопки на странице входа, пароль `password`):
   `customer@flowers.test`, `florist@flowers.test`, `courier@flowers.test`, `admin@flowers.test`.

**Ключевой сценарий:** покупатель собирает букет в конструкторе → добавляет в корзину вместе с готовым букетом →
оформляет заказ с доставкой и открыткой → флорист в «Очереди сборки» переводит заказ в «Собирается» и «Готов» →
курьер в «Доставках» берёт заказ и отмечает «Доставлен». Нарушения бизнес-правил (нехватка цветов, чётное число
цветов, доставка ночью) показываются сообщением сервера (ответ 409 / 422).

## Страницы

| Адрес | Страница | Доступ |
|-------|----------|--------|
| `/` | Каталог: фильтры (повод, цветок, цвет, цена), поиск, сортировка, пагинация; ИИ-подбор букета | все (ИИ — после входа) |
| `/bouquets/:id` | Карточка букета с составом | все |
| `/constructor` | Конструктор: цветы, количество, упаковка, расчёт цены на сервере «на лету» | все (сохранение — после входа) |
| `/cart` | Корзина и оформление заказа: доставка, интервал, открытка с ИИ-генерацией текста | все (оформление — после входа) |
| `/login`, `/register` | Вход и регистрация | гости |
| `/my-bouquets` | Сохранённые индивидуальные букеты | авторизованные |
| `/orders` | Мои заказы / очередь сборки / доставки / все заказы — в зависимости от роли | авторизованные |
| `/orders/:id` | Заказ: состав, доставка, открытка, смена статуса, отмена, назначение курьера | по правам |
| `/stock` | Цветы и склад: поступление и списание; CRUD цветов для администратора | флорист, админ |
| `/admin/*` | Букеты (с загрузкой фото), упаковка, поводы, пользователи и роли, отчёт | администратор |

## Как устроено взаимодействие с API

- `src/api/http.js` — единая функция `request()`:
  - добавляет `Accept: application/json`, `Content-Type: application/json` и `Authorization: Bearer <token>`;
  - при **401** удаляет токен и перенаправляет на страницу входа;
  - при **422** возвращает объект `errors` — ошибки выводятся рядом с полями формы;
  - при **409/403/404** — сообщение сервера (`message`), для нехватки цветов — список из `details`;
  - обрабатывает ошибки сети и **5xx**.
- `src/api/index.js` — функции для всех эндпоинтов.
- Токен хранится в `localStorage`; при запуске профиль загружается запросом `GET /api/user`.
- Загрузка фото букета — `FormData` без заголовка `Content-Type: application/json`.
- Элементы, недоступные роли, скрываются (меню, кнопки), но права всегда проверяет сервер (403).
- Фильтрация, сортировка и пагинация выполняются на сервере; переключение страниц — по `meta` из ответа Laravel.

## Структура

```
src/
  api/          http.js (request, ApiError, токен), index.js (эндпоинты)
  stores/       auth (пользователь и токен), cart (корзина в localStorage), dictionaries, toast
  router/       маршруты и защита по авторизации и ролям
  components/   AppHeader, BouquetCard, FlowerArt (иллюстрация букета по цветам состава),
                PaginationBar, FormField, StatusBadge, ToastList
  views/        страницы; admin/ — раздел администратора
  utils/        форматирование денег и дат, справочники подписей
```
